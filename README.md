# HealthData — Healthcare Management System

Multi-tenant healthcare management SaaS platform built with Nuxt 4 and Supabase. Includes a public landing page, authentication (email + password with OTP verification), and role-based dashboards for **admin, doctor/specialist, nurse, pharmacy, receptionist, and patient** users.

## Tech Stack

| Layer | Technology |
|---|---|
| Framework | [Nuxt 4](https://nuxt.com) (`compatibilityDate: 2025-07-15`) |
| Package manager | [pnpm](https://pnpm.io) |
| UI | [Vuetify 3](https://vuetifyjs.com) + Tailwind CSS (landing pages only) |
| State | [Pinia](https://pinia.vuejs.org) |
| Database & Auth | [Supabase](https://supabase.com) (SSR, email/password, cookie-based) |
| Server | Nitro routes under `server/api/` |
| Payments | [Stripe](https://stripe.com) |
| Email | [Resend](https://resend.com) |
| Deploy | [Vercel](https://vercel.com) |

## Prerequisites

- Node.js 20+
- [pnpm](https://pnpm.io/installation)
- [Supabase CLI](https://supabase.com/docs/guides/cli) + Docker (only for local Supabase / E2E tests)

## Getting Started

### 1. Install dependencies

```bash
pnpm install
```

### 2. Environment variables

Copy the example file and fill in the values:

```bash
cp .env.example .env
```

| Variable | Purpose | Where to get it |
|---|---|---|
| `SUPABASE_URL` | Supabase project API URL | Supabase Dashboard → Project Settings → API |
| `SUPABASE_KEY` | Supabase public (anon) key | Supabase Dashboard → Project Settings → API |
| `SUPABASE_SERVICE_KEY` | Supabase service role key (server-only, never expose) | Supabase Dashboard → Project Settings → API |
| `STRIPE_SECRET_KEY` | Stripe secret key | Stripe Dashboard → Developers → API keys |
| `STRIPE_WEBHOOK_SECRET` | Stripe webhook signing secret | Stripe Dashboard → Developers → Webhooks |
| `RESEND_API_KEY` | Resend API key for transactional email | Resend Dashboard → API Keys |
| `ENABLE_INSTANT_SUPERADMIN_LOGIN` | Set `true` to show the 1-click superadmin login on `/login` | — |
| `SUPERADMIN_EMAIL` | Email of the superadmin account used for instant login | — |

> **Important:** `SUPABASE_SERVICE_KEY` bypasses Row Level Security. Never commit it or expose it to the client. Store secrets in your environment / deployment platform.

**Local Supabase** uses `project_id = "erp-healthcare"` (port 54321). When running the local CLI, point `SUPABASE_URL` to `http://localhost:54321` and use the keys printed by `supabase start` (or the local `.env` generated by the CLI).

### 3. Run the database (optional, local Supabase)

```bash
supabase start        # starts Postgres + Auth + storage on localhost:54321
supabase db reset     # apply migrations and seed data
```

Supabase Studio (dashboard) is available at `http://localhost:54323`.

### 4. Start the dev server

```bash
pnpm dev
```

The app runs at http://localhost:3000.

## Project Structure

```
app/              → Nuxt 4 app directory (pages, components, composables, stores, layouts, middleware, plugins, utils)
server/api/       → Nitro API routes (role-scoped: auth/, admin/, doctor/, patient/, nurse/, pharmacy/, receptionist/, superadmin/)
supabase/         → Local Supabase config, migrations, seed data
types/            → Type augmentation (NuxtApp.$supabase, etc.)
```

## Authentication & Roles

- Email/password registration with OTP email verification.
- Session handled via Supabase SSR with cookie-based auth on both client and server.
- Six roles: `admin`, `doctor` (includes `specialist`), `nurse`, `pharmacy`, `receptionist`, `patient`.
- Route protection via middleware pipeline: `auth` → `guest` → `role` → `permission`.
- Password reset flow via email link (Resend).

## Testing

```bash
pnpm test               # unit tests (vitest)
pnpm test:e2e:setup     # start local Supabase + seed E2E data
pnpm test:e2e           # end-to-end tests (Playwright)
```
